How this works

The test is split into 3 sessions of ~50 minutes each (~2.5 hours total). You don't have to do it all at once — your progress saves automatically in your browser, so you can stop and come back to the same URL.

Each scenario has three parts:

  • 📋 Steps — what to do, in order
  • ✅ Expected — what should happen if everything's working
  • 🚨 Flag if — write this down and send it back if you see it

Click a scenario's title to expand it. Click the checkbox on the left when you finish a scenario.

What you'll need before starting

  • Two email inboxes you can read. The Gmail trick — yourname+test1@gmail.com and yourname+test2@gmail.com both arrive in your normal inbox but the app sees them as different people
  • Any sample PDF (a contract or random document)
  • A receipt photo (a real receipt or sample image)
  • A modern web browser (Chrome, Safari, Firefox, Edge)
⚠️ Read this first: If a step says "you should see X" and you don't, that's a bug — write down the scenario ID (e.g. "B3") and what happened. Also flag anything confusing, any blank screens, any button that does nothing, or anything where you had to refresh the page to see a change.

🚀 Session 1 — Core Experience

~50 minutes
Section A — Sign Up & Sign In
A1Register a new test brokerage account
  1. Open the app (button above).
  2. Click the Create Account tab.
  3. Fill in:
    • Account Type: Solo Agent
    • Brokerage Name: anything (e.g. "Tester Realty")
    • First / Last Name: your real name is fine
    • Email: a throwaway like yourname+test1@gmail.com
    • Phone: any 10-digit number
    • State: Florida
    • Password: at least 8 characters
  4. Click Start Free Trial.
✅ Expected: Account is created. You're logged in. Dashboard loads in a few seconds. A welcome email arrives within ~1 minute.
🚨 Flag if: Error message, hang, dashboard blank, no welcome email after 2 minutes.
A2Log out and log back in
  1. Find the logout option (top right area or settings menu).
  2. Confirm you land on the login screen.
  3. Log in again with the same email + password.
✅ Expected: Login works, dashboard loads with your data.
🚨 Flag if: Login rejects valid credentials, you land on the wrong screen, or you see someone else's data.
A3Forgot password → email reset link
  1. At the login screen, click Forgot your password?
  2. Enter the same email you registered with → submit.
  3. Check your inbox for the reset email (~1 minute).
  4. Click the reset link, set a new password.
  5. Try the same reset link a second time.
  6. Log in with the new password.
✅ Expected: Email arrives. Link works once. Used link shows "expired" or "already used". New password works for login.
🚨 Flag if: No email after 2 minutes, link doesn't work, used link works a second time, new password rejected.
A4Change password from inside the app
  1. While logged in, find Change Password in profile / settings menu.
  2. Enter current password + new password (different from current).
  3. Submit.
  4. Log out and try the OLD password (should be rejected).
  5. Try the NEW password (should work).
✅ Expected: Old password rejected, new password works.
🚨 Flag if: Both passwords work, or change silently fails.

Section B — Transactions
B1Create a transaction manually
  1. From the dashboard, click New Transaction (or the + button).
  2. Fill in: property address ("123 Test St, Orlando, FL 32801"), property type, transaction type (Listing or Buyer Rep).
  3. Pick a closing date 30+ days out.
  4. Add list price, contract price, earnest money (any reasonable numbers like $400,000 / $5,000).
  5. Save.
✅ Expected: Transaction appears in the list. Clicking it opens detail view with all fields you entered.
🚨 Flag if: Save fails silently, fields are missing after save, required-field markers (red asterisks) are unclear.
B2Edit transaction — clear a field and verify it stays cleared
  1. Open the transaction → click Edit.
  2. Clear a non-required field (delete the MLS# or county, leave it empty).
  3. Save.
  4. Re-open Edit.
✅ Expected: The cleared field is still empty.
🚨 Flag if: The old value comes back (this was a known bug we fixed — if it's back, it's a regression).
B3Edit transaction — change "Assigned Agent" dropdown
  1. Edit a transaction → find the Assigned Agent dropdown.
  2. Change it to a different agent (or back to yourself if you're the only one).
  3. Save.
  4. Re-open Edit and verify the new agent is selected.
✅ Expected: The new agent stuck.
🚨 Flag if: The old agent is still shown.
B4Move the transaction through status changes
  1. Open the transaction, change Status from New to Under Contract → Save.
  2. Verify a list of Milestones appears automatically (Inspection deadline, EMD due, etc.).
  3. Continue to Inspection, then Appraisal, then Clear to Close.
✅ Expected: Status changes save. Milestones populate. "X days to close" widget updates.
🚨 Flag if: Milestones don't appear, status fails to change, the "days to close" counter is wrong.
B5Add a Buyer, a Seller, and a Lender
  1. In the transaction, find Parties section.
  2. Add a Buyer using a different email you can read (e.g. yourname+test2@gmail.com).
  3. Add a Seller with yet another readable email.
  4. Add a Lender with any email.
✅ Expected: All three parties appear in the parties list with their role labels.
🚨 Flag if: Save fails for any role, duplicate detection misfires, or parties don't appear after save.
B6Edit a party then remove a party
  1. Edit one of the parties — change their phone or email.
  2. Save → verify the change shows.
  3. Delete one party.
✅ Expected: Edit saves correctly. Delete removes only the party you picked.
🚨 Flag if: Multiple parties get deleted, edit doesn't save, or the page crashes.
B7Send welcome emails to all parties
  1. Find Send Welcome Emails button or action.
  2. Trigger it.
  3. Check the inboxes for the Buyer and Seller addresses.
✅ Expected: Each party gets an email. The brokerage name, logo, and brand color render correctly. Email body has no weird characters or broken HTML.
🚨 Flag if: Any party doesn't get an email, the logo is broken, special characters look garbled, or HTML tags show as text instead of styled.
B8New Construction transaction type
  1. Create a NEW transaction (not the one above).
  2. Set Construction Type to New Construction.
  3. Set status to Under Contract.
  4. Look at the milestones list.
✅ Expected: Milestones like "Inspection deadline", "HOA doc review", "Title commitment" should be auto-marked N/A (greyed out or hidden) because they don't apply to New Construction.
🚨 Flag if: Those milestones appear as active reminders even though it's New Construction.

🤖 Session 2 — AI & Deep Features

~50 minutes
Heads up: Sections D & E rely on the AI features which were just rewired. These are the most important to test — flag anything that hangs or behaves oddly here.
Section D — Contract Auto-Intake (AI parses a real contract)
D1Upload a contract → AI extracts → review → approve
  1. Find Upload Contract or Contract Auto-Intake in the app (might be on the dashboard or under New Transaction).
  2. Upload any real estate contract PDF (a FAR/BAR or AS-IS contract works best — any reasonable PDF works for the test).
  3. Wait while it processes (30-60 seconds — you'll see "Reading your contract…" with a spinner).
  4. On the review screen: scan the property address, contract price, EMD, executed date, closing date, parties.
  5. Fix anything wrong, then click Approve & Create Transaction.
✅ Expected: Processing completes within ~60 seconds. Review screen shows fields the AI extracted. You can edit any field. Approving creates a new transaction populated with the data.
🚨 Flag if: Processing hangs longer than 2 minutes, review screen is blank, fields are wildly wrong, OR the SAME person is listed as both Buyer and Seller (this was a bug — flag if it returns).
D2Generate a shareable upload link (no-login client upload)
  1. In the Contract Auto-Intake area, find Send Shareable Link.
  2. Generate a link. Copy it.
  3. Open the link in an incognito / private browser window (this simulates an outside person clicking it).
  4. Upload a PDF as that anonymous user.
  5. Switch back to your main browser → check the contract uploads list.
✅ Expected: The public upload page loads without requiring login. Upload completes. The agent dashboard shows it processing.
🚨 Flag if: The public link asks you to log in, or upload fails for the anonymous user.
D3Multi-file contract package
  1. In Contract Auto-Intake, upload the contract PLUS 2-3 additional PDFs at the same time (any PDFs — could be the same one renamed).
  2. On the review screen, look for the Documents Detected section.
✅ Expected: Each uploaded PDF is identified as a separate document with a confidence label.
🚨 Flag if: Only the first file shows up — the others were ignored.
D4Custom clauses surfaced for review
  1. If you have a contract with a special-clauses or additional-terms section, upload it.
  2. On the review screen, look for a yellow box labeled Additional Terms / Special Clauses Detected.
✅ Expected: Custom clauses appear in a yellow callout box so the agent can verify them.
🚨 Flag if: The yellow box never appears even though the contract has special clauses, OR the box appears but the text is missing.
If your test PDF has no special clauses, just check ✓ and move on.
Section E — AI background flows (most important to test)
E1AI Receipt Scan (Expenses)
  1. Find the Expenses page in the navigation.
  2. Click New Expense or Add Expense.
  3. Click the receipt-upload area and pick a receipt photo (any photo of a real or sample receipt).

🚨 Flag if: Status stuck on "reading" forever, you get a timeout error, the form never populates, or the page hangs.
E2CMA Calculator with AI comp extraction
  1. Open any transaction → find the CMA or Pricing tool.
  2. Click Upload Broker Synopses.
  3. Upload 1-2 PDFs (any MLS sheets or even random property PDFs are fine for testing).
  4. Status should show "AI extracting…" for 10-30 seconds.
✅ Expected: AI populates comp slots (address, sold price, beds/baths, sqft). Some fields can be blank — that's OK. You should be able to edit each one.
🚨 Flag if: Extracting hangs over 60 seconds with no result, or only 1 of 2 comps come back.
E3Pre-Approval letter upload + AI extract
  1. Open a transaction where the Buyer is using financing (not cash).
  2. Find the Pre-Approval card on the transaction.
  3. Click upload → pick any PDF (any letter-style PDF will do).
  4. Flow: uploading → "extracting…" → review form.
✅ Expected: The review form pre-populates with lender, loan officer, NMLS, amount, type, expiration date. You can edit, then save.
🚨 Flag if: Extraction stage hangs, review form has missing fields, or save fails.
Section F — Milestones & Custom Tasks
F1Milestones auto-seed when status → Under Contract
  1. Take a transaction in status "New" or "Active".
  2. Set Executed Date AND Closing Date.
  3. Change status to Under Contract.
✅ Expected: A list of milestones populates: EMD due, Inspection deadline, Loan commitment, etc. Each has a calculated due date.
🚨 Flag if: No milestones, milestones with no due date, or duplicate milestones.
F2Mark a milestone Complete
  1. Open a milestone like "EMD due" or similar.
  2. Mark it Completed.
✅ Expected: Milestone shows as Completed. The Daily Dashboard may add a "compliance gap" reminder noting the milestone is complete but missing a document — that's expected behavior, not a bug.
🚨 Flag if: Marking Complete fails silently or the milestone reverts to Pending after save.
F3Mark a milestone N/A
  1. Mark a different milestone as N/A (not applicable).
✅ Expected: Milestone disappears from the active list (or is greyed out). Any related daily reminder also auto-clears.
🚨 Flag if: Daily reminder still appears the next day for an N/A milestone.
F4Waive a milestone with reason
  1. Try to waive (not just complete) a milestone.
  2. The app should require you to enter a reason and justification text.
  3. Submit.
✅ Expected: The waive form requires reason + justification before submitting. After submitting, milestone shows "Waived".
🚨 Flag if: You can waive without entering a justification, or activity log doesn't show who waived and why.
F5Custom task → mark Complete → reminder auto-clears (recent fix)
  1. Open a transaction → Tasks tab.
  2. Add a custom task with a due date 3 days in the past (e.g. if today is the 26th, set due date to the 23rd).
  3. Save the transaction.
  4. Go to the Daily Dashboard — you should see "OVERDUE: [task name]" listed.
  5. Go back to the transaction's Tasks tab → mark the task Completed → Save.
  6. Return to the Daily Dashboard and refresh.
✅ Expected: The "OVERDUE" reminder is GONE without having to click anything on the reminder itself. This is the recent auto-archive fix.
🚨 Flag if: The reminder is still there after marking the underlying task Complete.
F6Task templates (Admin)
  1. Find Settings → Task Templates.
  2. Browse the default templates.
  3. (Optional) Add a new template — give it a name, pick a phase, days from open. Save.
  4. Create a new transaction — verify your new template task appears.
✅ Expected: Custom templates are saved and applied to new transactions.
🚨 Flag if: Template list doesn't load, save fails, or templates don't apply.

📝 How to report what you find

  • Note the scenario ID (e.g. "F5" or "I3")
  • What you expected vs. what actually happened
  • What browser + device you're on (e.g. "Chrome on Mac" / "Safari on iPhone")
  • A screenshot helps a lot

Send your findings to whoever invited you to test — text, email, or a quick voice note all work. Don't try to fix things mid-test; just collect findings and report at the end.

Thank you for testing! Real agents will use this in production — catching bugs now saves them headaches later.
